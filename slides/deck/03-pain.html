Коротко о механике

Для каждого запроса агент заново собирает карту проекта

Весь код, документацию, правила и историю невозможно одновременно передать модели — недостающие связи приходится искать.

Запрос→Поиск
grep · usages→Новые файлы
и связи→Ещё поиск→Контекст растёт

Чем дольше поиск, тем меньше места остаётся для действительно важного.

Проблема не в grep. Без устойчивой карты связей агент каждый раз реконструирует проект по отдельным текстовым следам.

Сначала спросить, кто регулярно работает с AI-агентами. Затем пройти три карточки поднятием рук. Во второй карточке привести пример: код компилируется, но дублирует существующий механизм, обходит архитектурный паттерн, нарушает гайдлайны или не проходит quality bar команды. Не обсуждать ответы подробно — сейчас нужна общая боль. Popup объясняет общий механизм. Cursor использовать только как знакомый пример: поиск символа ведёт к usages, импортам, чтению новых файлов и следующему поиску; все результаты попадают в то же окно. Уточнить: уже найденный контекст может переиспользоваться, но недостающую рабочую карту всё равно приходится достраивать под конкретный запрос.

05 · Первая попытка

Memory bank помогает.
Пока не начинает отставать.

Сохраняет цель · решения · текущий фокус · следующие шаги
Не гарантирует актуальность · связи · непротиворечивость · исполнение

Когда memory bank перестаёт быть рабочей памятью?

Сначала признать пользу: memory bank быстро создать и легко читать. Затем назвать предел: документ хранит сведения, но сам не поддерживает актуальность, не проверяет поведение и не восстанавливает сеть связей.

SDD · Spec-Driven Development

Спецификация удерживает намерение

До кода фиксируем: что строим, зачем, для кого, где граница scope и по каким критериям примем результат.

Без неё агент каждый раз заново угадывает замысел.

TDD · Test-Driven Development

Поведение становится проверяемым

Сначала падающий тест на наблюдаемое поведение, затем минимальный код и рефакторинг без смены смысла.

Зелёный тест ≠ достигнутая продуктовая цель.

Это карта оставшейся встречи. Memory bank отвечает только на вопрос «что мы записали». Дальше нужны отдельные механизмы для намерения, проверяемого поведения, связей и процесса выполнения. По клику кратко раскрыть Spec-Driven и Test-Driven Development. Переход: проверить обе идеи на одном намеренно неоднозначном требовании.
