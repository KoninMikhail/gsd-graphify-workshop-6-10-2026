# Воркшоп «От контекстного хаоса к управляемой разработке»

Дата: 6 октября 2026
Формат: доклад + live-demo + вопросы
Длительность основной программы: 120 минут
Аудитория: разработчики, уже знакомые с AI-агентами

## Главная мысль

AI-агент ускоряет написание кода, но не гарантирует сохранение замысла, связность решений и проверяемость результата. Рабочий процесс появляется, когда:

1. спецификация фиксирует, **что** и **зачем** строим;
2. тесты задают исполняемую границу корректности;
3. GSD управляет декомпозицией, планированием, выполнением и проверкой;
4. Graphify помогает находить связи и восстанавливать контекст проекта.

Это не презентация «про две утилиты». Это история перехода от импровизации к воспроизводимому процессу.

## Порядок работы над презентацией

1. Уточнить личные примеры в сценарии: 2–3 конкретные боли, один провал memory bank, один успешный результат.
2. Подготовить маленький демонстрационный проект с известным начальным и конечным состоянием.
3. Заполнить слайды по карте, сохраняя правило «один слайд — одна мысль».
4. Добавить реальные скриншоты артефактов: `PROJECT.md`, `ROADMAP.md`, `PLAN.md`, тест, отчёт Graphify.
5. Провести две полные репетиции с таймером и одну репетицию аварийного сценария без сети.

## Что участник должен унести

После встречи участник способен:

- объяснить, почему бесконечно растущий memory bank теряет полезность;
- различить SDD, TDD, GSD и Graphify по их роли;
- назвать путь от идеи до проверенной фичи в GSD;
- понять, когда нужен текстовый документ, а когда — граф связей;
- повторить базовый workflow на своём небольшом проекте;
- не воспринимать инструменты как замену инженерному мышлению.

## Ограничения и честные формулировки

- Memory bank не «плох сам по себе». Он плохо масштабируется без структуры, актуализации и механизма поиска связей.
- Graphify не создаёт истинное знание автоматически. Качество графа зависит от корпуса и извлечённых связей; происхождение и уверенность важны.
- GSD не гарантирует хороший продукт. Он делает решения, планы и проверки явными и воспроизводимыми.
- TDD и SDD дополняют друг друга: спецификация задаёт намерение, тесты проверяют наблюдаемое поведение.
- Live-demo доказывает только работоспособность выбранного сценария. Для реального проекта нужны адаптация и дисциплина команды.
