# Мобильный сценарий ведущего

> Второй экран на время выступления.
> Формат каждого блока: **время → действие → реплика → переход**.

## Обозначения

- **[СЛАЙД N]** — этот слайд должен быть на экране.
- **[КЛИК]** — открыть или закрыть элемент на текущем слайде.
- **[NEXT]** — перейти на следующий слайд после указанной реплики.
- **[IDE]** — переключиться из презентации в demo-среду.
- Текст в цитате `>` — произнести; остальное — действие или ориентир.

## Перед стартом

- Открыть первый слайд.
- Открыть demo-проект, терминал и fallback.
- Включить «Не беспокоить».
- Запустить таймер с `00:00`.
- Поставить воду рядом.

**Главное:** не читать слайды. Рассказывать одну историю:

`боль → контракт → проверки → связи → процесс → demo → следующий шаг`

### [СЛАЙД 14] Процесс GSD

> GSD — управляемый workflow вокруг проектных артефактов: от решения через план и выполнение к проверенному результату.

Провести по цепочке на экране:

**Связать с многочасовой фоновой работой**

> Долгая работа становится наблюдаемой и возобновляемой, но не превращается в гарантированно автономную.

## Fallback во время demo

**Переключиться сразу, если:**

- команда не дала полезного вывода за 45 секунд;
- появилась сеть, авторизация или установка;
- агент вышел за scope;
- тест падает по посторонней причине;
- осталось меньше 8 минут, а реализация не началась.

**Сказать без оправданий**

> Чтобы не тратить ваше время на ожидание, переключаюсь на заранее сохранённый результат этого шага.

**Порядок fallback**

1. Следующий checkpoint.
2. Готовые `PLAN.md`, diff, тест и graph query.
3. Скриншоты или скринкаст.

**Не делать**

- не чинить случайную проблему дольше минуты;
- не ждать молча;
- не ставить зависимости;
- не принимать новое архитектурное решение;
- не показывать секреты.
